About Me

From Notebook
to Production

A model is only useful once real people can use it. I build the whole path — training, serving, and the cloud infrastructure underneath.

I'm a final-year B.Tech Data Science student at Rajeev Gandhi Memorial College of Engineering and Technology, Nandyal, looking for AI Engineer and ML Engineer roles.

My flagship project is a crop disease detector: a MobileNetV2 transfer-learning model that reaches ~90% accuracy across 10+ disease classes. It's served through a Flask API, combined with live weather data, and deployed for anyone to use. The research behind it is published in IJMRT and won 3rd place at an international student conference.

I care about what happens after deployment. I built an MLOps observability platform that detects data drift and pinpoints which pipeline stage caused it, and an LLM agent on Gemini that placed 3rd of 600+ at PromptWars. I also designed and deployed RGMCET Eduflow, a serverless AWS platform that about 5,000 students and faculty use across campus.

I like understanding the math behind models too — I've implemented regression and gradient descent from scratch to see how they actually learn.

MLOps / Model Monitoring

MLOps Observability Platform — Drift Detection & Root-Cause Attribution

3 pipeline stages monitored 8-service Docker stack CI/CD
  • Most tools only flag drift at the model output. This platform monitors ingestion, preprocessing, and predictions separately, then ranks which stage caused the drift by magnitude and onset time
  • Batch drift detection with KS tests (SciPy) and streaming detection with ADWIN (River), scheduled every 5 minutes by Celery Beat with Slack alerts
  • Full model lifecycle: async training of Random Forest, XGBoost, and Logistic Regression, a staging-to-production model registry, and a cost-benefit and human-approval gate before retraining
  • FastAPI + React/TypeScript, containerised with Docker Compose, AWS infrastructure defined in Terraform, tested in GitHub Actions
